# Requirements

Requirements catalog for the short-session action RPG described in [vision.md](vision.md). The Vision wins over this
catalog; a conflict is a change to this catalog or a proposed Vision change, never a quiet deviation.

- Domain terms follow [glossary.md](glossary.md).
- Thresholds that need a measurement or the owner's word are recorded as assumptions in
  [open_questions.md](open_questions.md) and can change after measurement.
- The **reference phones** are the iPhone 13 Pro and the Samsung Galaxy S8 named in [Performance.md](Performance.md).
  Every performance and battery threshold is measured on both and holds only when it holds on both.
- Requirements marked with priority **Low** belong to the optional online features (ADR-005). The game is complete
  without them.

| FR-002 | Move Hero                   | As a player, I want to move my hero with a virtual stick so that I can position myself in a fight.                                                          | High     | Open   |
| FR-003 | Use Skills                  | As a player, I want to use my hero's skills with skill buttons so that I can defeat enemies.                                                                  | High     | Open   |
| FR-004 | Clear Packs                 | As a player, I want to defeat packs of enemies so that I make progress through the run.                                                                       | High     | Open   |
| FR-005 | Behavior-Changing Legendary | As a player, I want legendary items to change how my skills behave so that a drop makes me play differently.                                                  | High     | Open   |
| FR-006 | Equip Item                  | As a player, I want to equip a dropped item into a gear slot during a run so that I can use it right away.                                                    | High     | Open   |
| FR-007 | Auto-Salvage                | As a player, I want items I do not equip to be salvaged automatically so that I spend no time in an inventory.                                               | Medium   | Open   |
| FR-008 | Pause Run                   | As a player, I want to pause a run at any moment so that I can deal with an interruption.                                                                     | High     | Open   |

| FR-014 | Equip Codex Powers          | As a player, I want to choose which codex powers my hero carries into the next run so that I can experiment with combinations.                               | High     | Open   |

| FR-018 | Bad-Luck Protection         | As a player, I want the chance of a legendary drop to rise after every played run without one so that a streak of bad luck never lasts long.                        | Medium   | Open   |
| FR-019 | Export Save                 | As a player, I want to export my save as a file or a copyable code so that I can keep a backup and take my progress to another device.                       | High     | Open   |
| FR-020 | Import Save                 | As a player, I want to import an exported save so that I can restore my progress or move it to another device.                                               | High     | Open   |
| FR-021 | Install Game                | As a player, I want to add the game to my home screen from a link so that I can launch it like an app without an app store.                                  | High     | Open   |
| FR-022 | Play Offline                | As a player, I want to launch and play the game without a network connection so that I can play anywhere, for example on a bus.                              | High     | Open   |
| FR-023 | Update Between Runs         | As a player, I want a new version of the game to take effect only at a natural stopping point so that an update never interrupts or breaks my run.          | High     | Open   |
| FR-024 | Change Settings             | As a player, I want to change the frame rate cap and the sound volume so that I can adapt the game to my device and my surroundings.                         | Medium   | Open   |

| FR-027 | Submit Ladder Result        | As a player, I want to submit my ladder results to a leaderboard so that I can compare my skill with other players.                                          | Low      | Open   |
| FR-028 | View Leaderboard            | As a player, I want to view the leaderboard of the challenge ladder so that I can see how other players are doing.                                          | Low      | Open   |
| FR-029 | Cloud Backup                | As a player, I want to back up my save to the cloud so that my collection survives a lost phone.                                                              | Low      | Open   |

| FR-031 | Delete Cloud Data           | As a player, I want to delete all my data from the cloud so that I stay in control of my personal data.                                                       | Low      | Open   |

## Non-Functional Requirements

Combat feel (NFR-001 to NFR-008) is checked by playing a build on both reference phones. Each of these rows names its
playable acceptance criterion; the checklist lives in [Performance.md](Performance.md) and in the acceptance protocol.

| ID      | Title                      | Requirement                                                                                                                                                                                                                                                        | Category        | Priority | Status |
|---------|----------------------------|--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|-----------------|----------|--------|
| NFR-001 | Input Responsiveness       | On the reference phone, the hero visibly reacts to a stick movement or a skill button press within 100 ms, measured from touch to screen in a 240 fps slow-motion recording (for example with an iPhone 16 Pro Max), in 9 of 10 attempts.                                                                   | Performance     | High     | Open   |
| NFR-002 | Hit Feedback               | Every hit that damages an enemy shows a hit reaction on the enemy and plays a hit sound, both starting in the first rendered frame after the hit; a tester names, for 10 of 10 hits in a recording, the enemy that was hit.                                       | Usability       | High     | Open   |
| NFR-003 | Hit Weight                 | Heavy hits apply hit-stop, knockback, and screen shake whose strengths come from tuning data; in a playtest of 3 runs, the owner rates "hits feel weighty" at 4 or higher on a scale from 1 to 5.                                                                 | Usability       | High     | Open   |
| NFR-004 | Fun Without Loot           | With all item drops switched off in a test build, the owner rates clearing a pack at 4 or higher on a scale from 1 to 5 in a playtest of 3 runs.                                                                                                                  | Usability       | High     | Open   |
| NFR-005 | Touch Targets              | Every skill button and every button of the in-run user interface measures at least 9 mm by 9 mm on the reference phone's screen.                                                                                                                                  | Usability       | High     | Open   |
| NFR-006 | No Browser Gesture Leaks   | During a 10-minute run on the reference phone with constant stick and skill button use, the browser performs 0 page zooms, 0 pull-to-refresh actions, 0 text selections, and 0 context menus.                                                                     | Usability       | High     | Open   |
| NFR-007 | Frame Pacing               | During a 10-minute run and during the stress-test scene on the reference phone, at least 99% of frames are presented within 1.5 times the frame interval of the active frame cap, and no single frame takes longer than 100 ms.                                   | Performance     | High     | Open   |
| NFR-008 | Effect Budget              | The number of live enemies, projectiles, and visual effects never exceeds the budgets in Performance.md, for any combination of items and codex powers; the stress-test scene with the most effect-heavy build meets NFR-007.                                    | Performance     | High     | Open   |
| NFR-009 | Time to Run                | From tapping the home screen icon to controlling the hero in a run takes at most 5 seconds on the reference phone with the game cached, and at most 2 taps after the title screen appears.                                                                        | Usability       | High     | Open   |
| NFR-010 | Run Length                 | The median duration of a completed run, excluding pause time, lies between 5 and 10 minutes over the owner's last 20 playtest runs.                                                                                                                               | Usability       | High     | Open   |
| NFR-011 | Taps Between Runs          | Starting the next run from the end-of-run summary, with the same tier and codex powers, takes at most 2 taps.                                                                                                                                                     | Usability       | Medium   | Open   |
| NFR-012 | Readable Numbers           | Every number shown in the game has at most 4 significant digits, and no damage or health value at the highest tier of the challenge ladder exceeds 99,999.                                                                                                       | Usability       | Medium   | Open   |
| NFR-013 | Power Soft-Cap             | The damage of a hero with every codex power unlocked is at most 1.5 times the damage of a hero with the best 3 legendaries for the same build, measured with the simulation's damage benchmark.                                                                    | Usability       | Medium   | Open   |
| NFR-014 | Battery Use                | A 10-minute run at default settings uses at most 4% of the reference phone's battery, starting from a full charge at room temperature.                                                                                                                             | Performance     | High     | Open   |
| NFR-015 | Idle in Background         | Within 1 second after the game is hidden, it stops the simulation, rendering, and audio, and it schedules 0 animation frames and 0 timers while it stays hidden.                                                                                                   | Performance     | High     | Open   |
| NFR-016 | First Load Size            | The files precached on the first visit total at most 5 MB, compressed as transferred.                                                                                                                                                                             | Performance     | High     | Open   |
| NFR-017 | Run Progress Durability    | When the game is closed or killed at any moment of a run, the resumed run continues from a state at most 10 seconds of play older than the moment it was closed.                                                                                                   | Availability    | High     | Open   |
| NFR-018 | Collection Durability      | A codex power, a waiting legendary, a tier clear, or a setting is stored on the device within 1 second after it changes, and no update, migration, import, or cloud restore ever deletes one without the player's confirmation.                                                        | Availability    | High     | Open   |
| NFR-019 | Save Migration Coverage    | For every save format version ever released, an automated test migrates a stored example save to the current version without losing a codex power, a waiting legendary, a tier clear, or a paused run.                                                                                 | Maintainability | High     | Open   |
| NFR-020 | Import Robustness          | Importing any of 1,000 generated malformed or out-of-range save exports shows an error message, leaves the current save unchanged, and never stops the game.                                                                                                                 | Security        | High     | Open   |
| NFR-021 | Offline Completeness       | After one complete visit, every use case except the online features works with the device in flight mode.                                                                                                                                                       | Availability    | High     | Open   |
| NFR-022 | Deterministic Simulation   | Replaying the recorded inputs of a run with the same seed and game version produces the same end state, bit for bit, in Chromium, Firefox, and WebKit.                                                                                                            | Portability     | High     | Open   |
| NFR-023 | Browser Support            | The game installs and runs in the latest 2 major versions of Safari on iOS and of Chrome on Android, and in Chrome 138 on Android 9, the last version available on the Galaxy S8 reference phone.                                                                                                                                                              | Portability     | High     | Open   |
| NFR-024 | Screen Orientation         | The game is fully playable in landscape orientation, with the virtual stick under the left thumb and the skill buttons under the right thumb, on screens from 360 to 932 CSS pixels wide, and shows a rotate prompt in portrait orientation.                                                                                                                   | Portability     | High     | Open   |
| NFR-025 | Backend Independence       | With the cloud backend unreachable, slow, or out of quota, every offline use case meets its thresholds, and a run shows 0 network error messages.                                                                                                                 | Availability    | Low      | Open   |
| NFR-026 | Backend Rate Limits        | Every cloud backend endpoint authenticates the request, validates every input field, and rejects requests above a per-player rate limit that keeps the whole service within its free quota.                                                                       | Security        | Low      | Open   |
| NFR-027 | Quota Visibility           | The owner can see the usage of every free quota of the cloud backend, with an alert when any quota passes 80%.                                                                                                                                                  | Maintainability | Low      | Open   |

## Constraints

| C-002 | No App Stores                  | The game ships as a Progressive Web App from a free static host and is never published in an app store without a new ADR.                                                                 | Business    | ADR-001                             | High     | Open   |
| C-003 | Offline First                  | Nothing in a run depends on the network; after the first visit the game launches and plays from the device alone.                                                                         | Technical   | Vision, Non-goals; ADR-002          | High     | Open   |
| C-004 | Optional Free-Tier Backend     | A cloud backend is used only for opt-in leaderboards and cloud saves, on a non-expiring free tier that stops service instead of billing when a quota is exceeded.                          | Technical   | ADR-005                             | High     | Open   |
| C-005 | No Microtransactions           | The game contains no microtransactions, gacha, or loot boxes.                                                                                                                              | Business    | Vision, Non-goals                   | High     | Open   |
| C-006 | No Energy                      | The game contains no energy system and no energy meter, also not as an option.                                                                                                             | Business    | Vision, Non-goals                   | High     | Open   |
| C-007 | No Real-Time Timers            | No content, reward, or game action waits for or expires with real-world time; only the opt-in play reminder of C-013 measures play time.                                                                                                                   | Business    | Vision, Non-goals                   | High     | Open   |

| C-009 | No Login Streaks               | The game never rewards launching it on consecutive days or penalizes not launching it.                                                                                                     | Business    | Vision, Non-goals                   | High     | Open   |
| C-010 | No Idle Rewards                | The game grants no reward for time spent away from it.                                                                                                                                     | Business    | Vision, Non-goals                   | High     | Open   |
| C-011 | No Time-Limited Content        | No content or reward is available only for a limited time; seasons, if any, are optional fresh starts without exclusive rewards.                                                          | Business    | Vision, Non-goals                   | High     | Open   |
| C-012 | Monetization Model             | Monetization, if any, is limited to a one-time purchase plus optional real expansions.                                                                                                     | Business    | Vision, Non-goals                   | High     | Open   |
| C-013 | No Restriction-Based Limits    | No feature locks, limits, or penalizes play because of time played or time away; a play reminder is opt-in, set by the player, and only informs.                                          | Business    | Vision, Pillar 7                    | High     | Open   |

| C-018 | Persistent Storage Request     | The game requests persistent storage from the browser and encourages adding the game to the home screen.                                                                                  | Technical   | ADR-004                             | High     | Open   |

| C-027 | Performance Guidelines         | Every change follows docs/Performance.md; a change that breaks a performance budget is not done.                                                                                          | Operational | CLAUDE.md, How we work              | High     | Open   |
